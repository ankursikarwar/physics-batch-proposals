# Physics scenario proposals, by batch

Every scenario proposed by the generator across four batches, kept and rejected alike.

**Live page: https://ankursikarwar.github.io/physics-batch-proposals/**

A batch is defined by the concept list it was offered and whether a per-concept cap was in
force, so the page states both alongside every batch — a proposal can only be read against the
menu it was written from.

| batch | concepts | cap | proposals |
|---|---|---|---|
| v1 | 26 textbook concepts | off | 1102 |
| v2 | 9 motion + 6 force concepts, grouped | off | 1128 |
| v3 | 26 textbook concepts | 12 each, withheld from the prompt menu | 238 |
| v4 | 26 textbook concepts | 12 each, also removed from the schema enum | 236 |

Each row shows its status:

* **kept** — the DSL compiled it and the layout solver placed it, so it became a plan
* **layout-fail** — compiled, but no arrangement of objects satisfied it
* **compile-fail** — the DSL could not express the scenario at all

Those are different failures and are counted separately: a compile failure means the idea could
not be written down, a layout failure means it could not be built.

Generated by `tools/proposals_site.py` in the (private) pipeline repo.
